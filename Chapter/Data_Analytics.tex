In the dataset supplied by ODDS, the missing values where dropped.
That means, that if a missing data occured, the whole instance had to be removed.
There are different ways to hanlde missing data. 
Removing them is disadventageous because it removes existing data in that instance.


Handleling missing data is a crucial task in data analytics.
The results can be biased, if it is not done with care. 
For outlier detection it is important, that the imputation method is not triggering the masking effect, resulting in fewer detectable outliers. 
Other methods, besides removing whole instances, are hot imputation, mean imputation and regression imputation.
Those methods always fill some value into the missing data.
In hot imputation the missing value is replaced by a randomly chosen representative value.
While mean imputation is filling the missing data with the mean of the observed values, median imputation is filling the missing data with the median of the other instances.
Regression imputation is filling the missing value by predicting them via a regression model.


Wich methods can be used is determined by the type of missing data and the task wich the dataset is been used.
In cases where the data is missing completely at random (MCAR) the data is missing independently of observed or missing values.
Data is missing at random (MAR) when the data are missing independently of the values of the missing data.
Data is missing not at random (MNAR) if it missing because of its characteristics.
All types of missing data can be met with all the methods described except of MNAR.
By using the imputation methods I could be introducing a masking effect.
But the goal of the imputation is to maintain as much as possible data, not to regress relationsships. 
Values missing not at random is not the problem.
Regression imputation and hot imputation could be a viable option but this thesis is about outlier detection not imputation methods.
Therefor I chose the median imputation, because the median is a outlier robust parameter therefor not influencing the .

\subsubsection{The Problem of synthetic data}
\textcolor{red}{ Take on here }
    Revisiting Time Series Outlier Detection: Definitions and Benchmarks (Lai et al., 2021)
        Most synthetic data is generated by adding Gaussian noise or simple "spikes" to a clean signal
        he paper found that many deep learning models achieve near-perfect scores on synthetic data but perform worse than 30-year-old classical methods (like Isolation Forest) on real data. 
        This is because synthetic outliers are often too easy to distinguish from the normal distribution, leading to "inflated" performance metrics
    Synthetic Data, Synthetic Trust: Navigating Data Challenges in the Digital Revolution
        Researchers often develop an unwarranted confidence in models trained on artificial data.
        Synthetic generators (like GANs or VAEs) often fail to capture rare, complex correlations between variables (Intersectional Fidelity). 
        If the generator hasn't seen a specific type of rare "multi-variable" outlier, it won't produce it, and your model will never learn to detect it
    An Empirical Analysis of Synthetic-Data-based Anomaly Detection (Llugiqi  Mayer, 2022)
        In synthetic datasets, the "normal" data is often too "clean."
        Real-world data is naturally "messy" (sensor jitter, network lag). In synthetic benchmarks, the boundary between "Normal" and "Outlier" is mathematically sharp. 
        In the real world, that boundary is fuzzy.
        A model trained/benchmarked on synthetic data might treat any slight real-world noise as a "High-Confidence Outlier," leading to a flood of false positives in production.
